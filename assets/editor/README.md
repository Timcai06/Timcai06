# Profile assets — how the README is built

`README.md` (repo root) is Tim's GitHub profile page. It is hand-written HTML-in-Markdown; images are generated by scripts. GitHub strips CSS/JS, so everything visual is either an image or a native element (`<details>`, `<kbd>`, `<code>`, `<sub>`, `<blockquote>`, tables, `align`).

## Page structure

1. Hero — pixel-font title (`assets/hero/title-*.svg`, 16 s loop: columns light up and drop in, block cursor, two highlight sweeps, stars, a meteor, columns go out) and a typed tagline whose block cursor follows the reveal edge; no external service, contact badges (Blog uses the site's chrome "T" mark as a data-URI logo; LinkedIn uses a minimal "in" SVG), typing subtitle.
2. English intro, then `workspace.svg` — pixel-night backdrop + VS Code-style editor (`about.ts`, file tree, terminal, minimap). Motion (`scripts/motion.py`) is one 40 s session: the window opens on the night sky and the interface loads in (activity bar, explorer rows, tabs, code lines, outline, minimap, then the terminal rises); the terminal runs `cat now.txt`; the active line walks `projects` with the explorer row, minimap marker and `Ln/Col` following row for row; ⌘P types `clawd` and opens `clawdMV` (the cursor jumps to that line); the terminal clears and runs `echo $FOCUS` (the `focus` field); the window closes and the loop restarts. Around it: the same moon as the live terminal (`scripts/pixel_moon.py`, same day and phase) in the top strip, stars, a meteor, water ripples and moon glints in the bottom strip, and after the second command a toast notes the real daily Action refresh. `prefers-reduced-motion` shows the original static workspace.
3. Chinese intro below the workspace image + "Now" blockquote, then a `Writing` row of grey `<kbd>` links to blog posts. Both intros open with the spike: AI agent engineering.
4. Chapters as centred `<h1>` openers `01–04`; subsections use `<kbd>label</kbd> <b>English</b>`.
   - 01 重点作品 — two `<details>` layers: 主推 (open by default) with lead cards EduCanvas, SciScope; 精选 (collapsed) with rows TTT-I-M, BDI, PulseGraph.
   - 02 用代码做动画 — series statement, then one card per work (01 clawd-mv).
   - 03 技术栈 — a plain-text copy of the stack sits under the image (between `<!-- toolbox:text -->` markers, written by `build_toolbox.py`) so Ctrl+F and search find it; centered light/dark SVG, 3×2 grid with interrupted borders, corner marks and numbered groups; original skillicons and shields are embedded.
   - 04 更多 — Sophon AI card, Seen; folds "其他作品" and "数学建模" (one fold per modeling project inside).
5. `skyline.svg` — live terminal, one 28 s session (typed `git log --graph` with a commit rail and cascading rows → typed `skyline`, buildings rise to their true heights, the tower lights floor by floor, a warm horizon glow behind the city → typed `echo`, "Thanks for stopping by." assembles in the hero's pixel font (`scripts/pixel_font.py`) with a highlight sweep → fade and restart): `git log` of the 5 latest commits across public repos, contribution skyline (one building per week, windows = days), a 24-floor commit-hour tower (weekday × hour, UTC+8) and the real moon phase (snapped to 1/16 cycle; Lambert-lit pixel shading with Bayer dithering, near-side maria, earthshine on the night side, a breathing glow scaled by the lit fraction and a drifting cloud; `SKYLINE_DATE=YYYY-MM-DD python3 scripts/build_skyline.py` previews another day), closing with `echo "Thanks for stopping by."` as the page bookend. Refreshed daily by `.github/workflows/skyline.yml`. Motion is decorative only (stars, a meteor, the moon halo and a drifting cloud, an airliner with nav light and strobe, moonlight glints on the water (brightness follows the lit fraction), a car on the street, the roof beacon, the retyped echo on a 14 s loop); buildings and windows are data and never animate.
Project cards: frames stay decorative; the status bar is live (lamp = commit in the last 14 days, 12 weekly bars, commits / 12w and last commit date). Motion: the terminal types the README quick-start commands one after another (11 s loop, phase-shifted per card so the five cards never move in lockstep), a caret blinks on the empty README line, and the lamp breathes only for an active repository. Each loop the 12 weekly bars grow to their true height and a highlight reads across the stack chips. The open strips around each window carry a detail from that card's plate, located from the plate pixels: SciScope twinkles its own stars (plus a meteor), PulseGraph sends a pulse along its waveform, BDI flickers the dusk light, EduCanvas has dust motes in the window light, TTT-I-M has drifting evening cloud wisps.
6. Invitation text and grey contact buttons.

## Style rules

- No blue text links: project titles are plain text; links are grey `<kbd>` buttons or images.
- Emphasis is grey only: `<code>` for a few key phrases, `<kbd>` for numbers/links/status, blockquotes for notes.
- Facts (descriptions, stacks, commands) come from each repository's README / language stats; nothing invented.
- Visual acceptance is Tim's.

Project cards (`*-compact.svg`, 640×540): markdown README pane with stack chips that wrap, plus a terminal panel with two quick-start commands quoted from each repo README (`TERMINAL_CMDS` in `build_profile.py`). Key visuals: one lead frame (`"lead": true` in the JSON) plus the rest stacked on the right.

SVGs embed their backgrounds as base64 and contain no scripts, `foreignObject` or external fonts. Positions of indent guides, minimaps and cursors assume a ~0.6 em monospace advance and may shift a few pixels with other fonts.

Preview in VS Code or on GitHub; VS Code renders `<kbd>`, blockquotes and alerts differently from GitHub.

## Workspace illustration

`workspace.svg` is a static profile illustration, not a live IDE or a literal repository tree. Its research entries are topic labels. The current canvas is 1200×1060; code stays at 16 px with 20 px line spacing. Editor, terminal, status bar and canvas heights follow the code line count. Outline entries and their line numbers derive from the same top-level fields used in `about.ts`.

No test counts, build status or other live diagnostics are asserted by the illustration. To add content, update the workspace portion of `scripts/build_profile.py` and regenerate; verify text bounds in a browser because font metrics vary across renderers.

## Project card frames

The five 640×540 project cards share a broken outer rail and numbered label, with per-project decorative marks generated by `project_frame()` in `scripts/build_profile.py`: EduCanvas page layers/bookmark, SciScope reference brackets/linked dots, TTT-I-M viewfinder/keyframes, BDI chamfered corners/truss, and PulseGraph nodes/signal line. The outer rail is neutral gray; signature marks reuse each card's existing accent. These motifs are decorative, not actual measurements or status. Content and inner editor layout remain unchanged.

SciScope copy was checked against its repository README on 2026-10-12: a single LangGraph StateGraph runtime, RAG/evidence grounding/tool orchestration, SSE plan/tool/reflect/final events, and Go TUI tool timelines with same-session retry. The project card and profile description emphasize this Agent development work.

Note: the daily Action rebuilds `workspace.svg` and the cards on Linux, whose PNG bytes differ from a local macOS build even with the same Pillow. A local `build_profile.py` run therefore shows diffs in every card; commit them only when the content actually changed.

Cache busting: README image URLs carry `?v=<sha256[:8]>` of the file (`scripts/stamp_readme.py`). Browsers and GitHub's CDN cache images by URL, so without it an updated SVG keeps showing the old version (this hid the new animations once). Run the stamp after every asset build; the daily Action does.
